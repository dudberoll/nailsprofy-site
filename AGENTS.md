# AGENTS.md

## Назначение проекта

Это самостоятельный статический сайт NailsProfi. Рабочая область сайта — `website/`. Папка `scraper/` содержит только вспомогательные инструменты импорта контента.

В проекте нет активных backend, webapp, mobile, базы данных и облачной инфраструктуры. Не добавляй эти поверхности без явной продуктовой необходимости и согласия владельца.

## Общение с владельцем

- Отвечай на языке пользователя и объясняй результат простыми словами.
- Не выдумывай цены, акции, контакты, юридические тексты, ссылки записи или сведения об услугах.
- Спрашивай только тогда, когда без ответа нельзя безопасно выбрать продуктовый вариант.
- Перед публикацией, push, изменением домена, хостинга или внешних сервисов получи явное подтверждение.

## Перед изменениями

- Прочитай корневой `README.md` и файлы рядом с изменяемой областью.
- Проверь `git status --short --branch` и `git remote -v`, если папка уже стала Git-репозиторием.
- Сохраняй несвязанные изменения пользователя. Не применяй reset, clean, checkout, stash и массовое форматирование.
- Найди владельца поведения: страница → компонент → данные → медиа. Не маскируй проблему локальным обходом.

## Структура и контент

- Страницы Astro: `website/src/pages/`.
- UI-компоненты: `website/src/components/`.
- Тексты, услуги, цены и статьи: `website/src/data/`.
- Глобальные стили: `website/src/styles/`.
- Публичные изображения и видео: `website/public/`.
- Astro-ассеты: `website/src/assets/`.
- Импорт WordPress: `scraper/` и `exports/nailsprofi-wordpress/`.

Все медиа, необходимые странице, храни внутри проекта. Не создавай зависимость от временных файлов, тестовых скриншотов или изображений с чужих доменов.

## Реализация

- Сохраняй текущий дизайн и адаптивность, если пользователь не просит редизайн.
- Предпочитай существующие компоненты и возможности Astro/React новым зависимостям.
- Не добавляй зависимость без согласования, если задача решается текущим стеком или стандартной библиотекой.
- Визуальный стиль компонента должен принадлежать самому компоненту; внешний код управляет композицией и семантическими вариантами.
- Не редактируй сгенерированные `node_modules`, `.astro` и `dist`.
- Не добавляй проверочные скриншоты в репозиторий.

## Команды

Из корня проекта:

```bash
bun install
bun run dev
bun run typecheck
bun run check:assets
bun run build
bun run check
```

Для Python-инструментов следуй `scraper/README.md`.

## Проверка результата

- Для изменения поведения выполни `bun run check`: команда проверяет типы, наличие локальных медиа и production-сборку.
- Для визуальных изменений дополнительно проверь затронутые страницы в браузере на desktop и mobile.
- Убедись, что новые изображения и видео существуют в `website/public/` или `website/src/assets/` и используют стабильный регистр символов в пути.
- Не объявляй задачу завершённой, если основная пользовательская проверка не пройдена.

## Отчёт

Кратко сообщи: что изменено, зачем, какие проверки прошли и что осталось непроверенным. Не коммить и не пушь без явной просьбы.
