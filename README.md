# Сайт NailsProfi — старт для Татьяны

Это рабочий проект публичного сайта NailsProfi. Сайт собран на Astro и публикуется как набор статических файлов.

Татьяна может работать с сайтом через Codex без опыта разработки. Не нужно самостоятельно устанавливать программы, вводить команды в Терминале или искать нужные файлы проекта.

## Первый запуск на другом Mac через Codex

1. Открыть приложение Codex и создать новый диалог.
2. Скопировать и отправить Codex сообщение ниже целиком.
3. До скачивания проекта Codex должен проверить чистый Mac и с разрешения Татьяны установить все системные инструменты для разработки: Xcode Command Line Tools и Git, Node.js 22.12 или новее, Bun, Python 3.11 и GitHub CLI. После установки Codex должен проверить, что команды работают.
4. Только после подготовки компьютера Codex должен спросить, где хранить проект. Можно выбрать, например: «В Документах, в папке NailsProfi».
5. После скачивания Codex должен установить библиотеки самого проекта, подготовить Python-окружение для импортёра и выполнить проверки.
6. Подтверждать только понятные системные запросы macOS и Codex на установку инструментов или доступ к выбранной папке. Все технические действия Codex должен выполнить самостоятельно.

> Я Татьяна, владелец сайта и не пишу код. Помоги полностью подготовить мой Mac к работе с сайтом NailsProfi. Сначала ничего не скачивай. Проверь, установлены ли Xcode Command Line Tools и Git, Node.js версии 22.12 или новее, Bun, Python 3.11 и GitHub CLI. Объясни простыми словами, что отсутствует, и с моего разрешения самостоятельно установи все необходимые системные инструменты. После установки проверь их версии и убедись, что они запускаются. Только затем предложи мне выбрать папку для проекта и дождись ответа. Скачай проект из репозитория `https://github.com/dudberoll/nailsprofy-site.git` в выбранную папку. После скачивания прочитай корневые `README.md` и `AGENTS.md`, выполни `bun install`, создай Python-окружение `scraper/.venv` и установи зависимости `./scraper[dev]`. Затем выполни `bun run check` и тесты импортёра, запусти локальную версию сайта и пришли мне ссылку, которую нужно открыть в браузере. Не проси меня вводить команды в Терминале и объясняй всё простыми словами. Вход в GitHub запрашивай только тогда, когда он действительно понадобится для отправки изменений. После запуска следуй разделу «Совместная проверка сайта с Татьяной» из README.

Репозиторий публичный, поэтому для обычного скачивания вход в GitHub не требуется. Если настройки доступа когда-нибудь изменятся, Татьяне понадобится войти в GitHub-аккаунт, которому открыт доступ к репозиторию.

## Повторный запуск через Codex

В следующий раз достаточно открыть Codex в папке проекта и написать:

> Открой README, проверь обновления и зависимости, запусти локальную версию сайта и пришли мне ссылку. Не проси меня вводить команды в Терминале.

Codex должен проверить состояние Git, не перезаписывать локальные изменения, получить обновления только безопасным способом и затем запустить сайт.

## Структура

- `website/` — страницы, компоненты, стили и все опубликованные изображения и видео;
- `scraper/` — вспомогательные Python-скрипты для импорта данных старого сайта и WordPress-блога;
- `exports/nailsprofi-wordpress/` — компактный подготовленный экспорт статей для повторной сборки блога;
- `deploy/` — шаблоны будущей настройки VPS Beget, Nginx, публикации и отката;
- `AGENTS.md` — правила работы coding-агентов с проектом;
- `.codex/skills/` — дополнительные проектные навыки Codex.

В проекте намеренно нет старых backend, webapp, mobile и инфраструктурных заготовок. Для текущего статического сайта они не используются.

## Ручная установка и запуск

Этот способ предназначен для разработчика. Нужны Git, Bun и Node.js 22.12 или новее.

```bash
git clone https://github.com/dudberoll/nailsprofy-site.git
cd nailsprofy-site
bun install
bun run dev
```

Команда выведет локальный адрес сайта, обычно `http://localhost:4321`.

## Совместная проверка сайта с Татьяной

После первого запуска Codex должен сказать Татьяне:

> Сайт запущен. Сейчас мы вместе спокойно пройдём его и соберём реальные материалы, которых не хватает. Сначала я покажу весь список вопросов, затем мы обсудим их по одному. Я не буду придумывать ответы, тексты или факты вместо вас. Можно отвечать сразу в чате или сначала всё обдумать, подготовить фотографии и потом прислать ответы одним текстом.

Codex должен сначала показать Татьяне список ниже, а затем обсуждать по одному пункту за раз. Если ей нужно время, не торопить её и сохранить понятный перечень того, что осталось подготовить.

### Материалы, которые нужно запросить

1. **Фотографии салона.** Попросить актуальные оригинальные фотографии интерьера и уточнить, какие из них можно публиковать.
2. **Фотографии мастеров.** Запросить фотографии всех мастеров, которые должны быть представлены на сайте. Для каждого мастера уточнить имя, должность, опыт и проверить описание услуг.
3. **Проверка всех текущих фотографий.** Вместе пройти сайт и спросить, какие изображения нравятся, какие нужно заменить и что на них должно быть вместо текущего варианта.
4. **Видео на главной странице.** Объяснить, что в текущем видео заметен небольшой значок или артефакт, из-за которого оно выглядит сгенерированным. Попросить чистый исходник, другое видео или точное решение, как его переделать.
5. **Второй номер телефона.** Попросить точный номер, подпись к нему и уточнить, где его показывать: в шапке, контактах, кнопках записи или в нескольких местах.
6. **Бренды.** Попросить окончательный список брендов, которые действительно используются в салоне и должны быть показаны на сайте.
7. **Тексты от владельца.** Объяснить, что часть текущих текстов была создана как черновик и звучит искусственно. Попросить Татьяну написать своими словами реальные тексты о салоне, подходе и ценностях. Особенно нужны её формулировки для блоков «О салоне» и «Наши ценности». Codex может аккуратно исправить опечатки и структуру, но не должен заменять её голос сгенерированными обещаниями и фактами.
8. **Частые вопросы.** Попросить перечислить вопросы, которые клиенты действительно задают, и написать ответы так, как сотрудники салона отвечают на них в жизни.

Когда Татьяна пришлёт материалы и тексты, Codex должен кратко свести ответы в понятный список и отдельно подтвердить, что ничего не потерял. Только после этого можно вносить согласованные изменения.

### Как проверить сайт на компьютере

Сначала нужно посмотреть обычную десктопную версию:

1. Пройти главную страницу сверху вниз.
2. Открыть меню и все основные страницы.
3. Проверить кнопки, ссылки, изображения, видео, цены и контактные данные.
4. Записать всё, что выглядит неправильно или требует замены.

### Как открыть мобильную версию на компьютере

Самый простой вариант — написать Codex: «Открой мобильную версию сайта и помоги мне её проверить». Codex должен сам включить мобильный размер и пройти основные страницы вместе с Татьяной.

Если Татьяна хочет включить режим самостоятельно в Google Chrome на Mac:

1. Открыть сайт в Chrome.
2. Нажать `Command + Option + I`, чтобы открыть инструменты разработчика. То же окно можно открыть через меню Chrome: три точки → **Дополнительные инструменты** → **Инструменты разработчика**.
3. В верхней панели инструментов разработчика нажать значок телефона и планшета **Toggle device toolbar**.
4. Выбрать модель телефона либо режим **Responsive** и ширину около `390` пикселей.
5. Перезагрузить страницу и проверить меню, тексты, карточки, фотографии, видео, кнопки и горизонтальную прокрутку.

Компьютерный мобильный режим даёт хорошее приближение, но после него желательно открыть опубликованный сайт и на настоящем телефоне.

### Как передать готовые изменения через GitHub

После внесения правок Codex должен:

1. Выполнить `bun run check` и снова показать Татьяне desktop- и mobile-версию.
2. Дождаться её явного подтверждения, что результат можно сохранять.
3. Спросить разрешение на commit и push в GitHub.
4. После разрешения проверить ветку и remote, создать понятный коммит и отправить его в GitHub.
5. Сообщить Татьяне название ветки и хеш коммита, чтобы она могла переслать их владельцу проекта.

Татьяне не нужно самостоятельно вводить Git-команды. Достаточно написать Codex: «Я всё проверила. Сохрани изменения и отправь их в GitHub». После этого владелец сможет открыть репозиторий на своём компьютере, получить изменения и провести финальную проверку.

## Проверка перед публикацией

```bash
bun run check
```

Готовая статическая сборка появится в `website/dist/`. Папку `dist` не нужно добавлять в Git: скрипт из `deploy/` заново собирает её на Mac и загружает готовые файлы на VPS.

## Где менять сайт

- страницы: `website/src/pages/`;
- компоненты: `website/src/components/`;
- общие стили: `website/src/styles/`;
- тексты, услуги, цены и данные блога: `website/src/data/`;
- изображения, видео и favicon: `website/public/`;
- изображения, импортируемые через Astro: `website/src/assets/`.

Публикуемые медиа должны храниться внутри проекта. Не используйте временные локальные пути, папки со скриншотами или ссылки на изображения с чужих сайтов.

## Повторный импорт WordPress-блога

Python-инструменты нужны только для повторного импорта; для обычного запуска сайта они не требуются.

```bash
python3.11 -m venv scraper/.venv
scraper/.venv/bin/python -m pip install -e "./scraper[dev]"
scraper/.venv/bin/nailsprofi-blog-import
```

Импортёр читает `exports/nailsprofi-wordpress/posts.jsonl` и обновляет `website/src/data/blogArticles.json`. Он сохраняет уже отредактированные вручную поля, когда это возможно. После импорта обязательно запустите `bun run check`.

## Безопасность

- не добавляйте в Git `.env`, токены, ключи, локальные зависимости, сборки и проверочные скриншоты;
- не публикуйте сайт, не меняйте домен и не отправляйте изменения в GitHub без явного подтверждения владельца;
- перед удалением контента сначала проверьте его использование в страницах, компонентах и данных.

История безопасного отделения проекта от старого шаблона описана в `docs/MIGRATION.md`.
